## Compare and contrast the types of frontend development you used in your full stack project, including Express HTML, JavaScript, and the single-page application (SPA). Why did the backend use a NoSQL MongoDB database?
During full stack development of this project we used different types of front end coding methods to both learn and update the web page. Initially, we began by creating the Travlr Getaways site using Express HTML, then converting that to handlebars views to aid in rendering speed and load time. The downside to using Express HTML is that it is static, client-facing, and can not interact with backend databases to update information dynamically. We then created JavaScript files to be able to add dynamic elements to the webpage. We also used it to pull trip information from the database that was created in MongoDB and populated with Seedgoose from existing information. The backend chose a NoSQL MongoDB database because of the ease to modify the schema based on scaling, functionality changes, and non-relational nature of the database. Finally we integrated SPA functionality to be able to increase performance and reduce the amount of calls between the front-end and back-end whenever a user is working within the system. 

## How is JSON different from JavaScript and how does JSON tie together the frontend and backend development pieces? Provide instances in the full stack process when you refactored code to improve functionality and efficiencies, and name the benefits that come from reusable UI components.
JSON is a standardized way to format any object data to be read by JavaScript, creating a JavaScript object. JSON creates a method that allows data and objects to be stored on the backend while still being able to be used through the frontend. Since JSON works this way, we can store the data once and use it multiple times without having to create new objects. The trip list and trip card view are an excellent example of this. Initially we created the trip list to be able to quickly view our database entries, but through JSON and refactoring we created the trip card list to render the page once, and each trip separately to improve the performance of the trips page. This allows smaller components to render quicker than the page as a whole. Reusing code and UI components not only reduces time and cost, but also decreases the overall size of an application and decreases the chances of errors or vulnerabilities within the system.

## Methods for request and retrieval necessitate various types of API testing of endpoints, in addition to the difficulties of testing with added layers of security. Explain your understanding of methods, endpoints, and security in a full stack application.
The website methods drive the functionality of a webpage: GET, POST, PUT, and DELETE are the http requests that allow the user to retrieve or modify database entries, which are handled via the backend. Endpoints are the results of methods handled by the admin or client-side of the application. The endpoints should be tested so that they function correctly, display correct data, and throw errors if necessary. Security is a layer of code within the server to prevent unauthorized access to the database, either from within or without the webpage. Tying this all together, if a user were to add or edit a trip the API endpoints need the security to prevent unauthorized database requests by the user.
